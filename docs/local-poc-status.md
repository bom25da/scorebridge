# 로컬 PoC 구현 상태

검증일: 2026-10-11. 환경: macOS Apple Silicon, Node 22.20.0, Audiveris 5.11.0.

## 완료

- 실제 인식 엔진으로 PNG·PDF → MusicXML 변환
- PostgreSQL 작업 저장, Redis/BullMQ 큐, DB outbox 전달
- 웹 업로드·이력·상태·페이지 이동·원본 확대·OSMD 미리보기·다운로드
- 실패 페이지 재시도, 비동기 삭제, 실행 중 워커의 7일 만료 정리
- JPG/PNG 실제 형식 검사, PDF 5페이지 제한, 20MB 업로드 제한
- XML 외부 엔티티 거절, 압축 악보 해제 상한, 로컬 접근 제한

## 검증 결과

- TypeScript 검사와 Vite production build 통과.
- 단위 테스트 3개 통과: XML/MXL 의미 유지, 잘못된 XML·외부 엔티티 거절, 자식 프로세스 timeout·실패 종료.
- 실제 엔진 smoke test 통과: PNG·PDF 입력, MusicXML 다운로드·4마디 확인, 잘못된 파일 및 외부 origin 거절, 작업 삭제.
- 별도 검사: 6페이지 PDF 거절, 빈 이미지 실패, 실패 페이지 재시도.
- 브라우저 검사: 실제 인식 결과 SVG 표시, 다운로드 응답 확인, 390px 화면에서 가로 overflow 없음.
- 수정 후 자작 PNG의 처리 시간 약 2.9초. 이 값은 단일 합성 악보의 실행 결과이며 일반 성능 또는 정확도를 보장하지 않는다.

## 발견하고 수정한 사항

- PDF 출력 이미지가 엔진의 2천만 픽셀 제한을 초과했다. 입력을 최대 4000×4000 범위로 정규화한다.
- macOS Java의 그래픽 실행으로 종료가 지연되었다. 번들 Java를 직접 호출하고 headless 모드로 실행한다.
- API·워커의 초기 스키마 생성은 transaction advisory lock으로 직렬화한다.
- 삭제 중 작업은 결과 접근과 완료 상태 갱신에서 제외한다.

## 아직 남은 작업

- 실제 스캔·사진 평가 자료를 이용한 정확도 및 수정 시간 측정
- 웹 악보 편집·재생, 페이지 선택 후 인식, ZIP·전체 곡 출력
- 운영용 인증·권한·엄격한 실행 lease·접수 멱등성·장애 복구 시험
- 모노레포 패키지 분리, Docker Compose, Linux ARM64 검증, OCI 배포
- OCR 언어 데이터 설치 및 제목·가사 인식 평가

현재는 로컬 전체 흐름이 동작하는 PoC이며 기획 문서의 품질 기준 평가 또는 공개 MVP 완료 단계는 아니다. 실행 방법은 [README](../README.md)를 따른다.
